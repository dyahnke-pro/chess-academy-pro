- **Where the model still decides — the whole disease:**

  5. Announcements are never checked against what was done (`coachService ≈2262` is audit-only; `validateOpeningNameClaims` has no caller).

## 1. The design — one pipeline, four stages, every surface

```
message ──► [1 FAST PATH] deterministic router (existing regex lanes + commands)
               │ hit → answer/act (unchanged)
               │ miss
               ▼
            [2 READ]  the model fills ONE closed form: ChatTurn   (≤1 call)
               │ code VALIDATES it (chess.js, referents, capabilities)
               │ invalid/unsure → [2b ASK] a clarifying question with chips
               ▼
            [3 DO]    code answers / acts:  Record<Kind, Answerer>, Record<Command, action>
               ▼
            [4 SAY]   words built FROM what was computed or done (voiceFacts, echo the question)
```

**ChatTurn (closed, discriminated):**
- `question` — `kind`: why · why-not · what-if · is-good · best · plan · threat · meaning · eval · explain-last · history/stats (self-knowledge) · meta/app-help; `subject`: `move{san}` | `last-move{seat}` | `piece{square|type, seat}` | `position` | `plan{seat}` | `concept{id}` | `game{ref}`; `seat`: me | them.
- `command` — exactly the existing `RoutedIntent` kinds + `start-game{seat, opening?}` + `start-lesson{opening}` (the tool set, but as data).
- `chat` — small talk with no chess content.
- `unclear` — the model says it cannot tell; carries up to 3 candidate readings.

**Rules that make the model unable to decide chess:**
1. The model's only output on a miss is a ChatTurn. **No free text, no tools, no `[[ACTION]]`.** The banter and legacy free lanes and the prose move-recovery net are DELETED.
2. **Actions happen before words.** A `command` goes `→ actionForCommand → actuate`; the sentence is built from the `ActuationResult` ("You're White — your move."), so the words cannot disagree with the board. This is David's "forced to follow through", made safe: the model proposes, code checks and does, words report what was done.
3. **Every answer echoes what was understood** ("Why not e5? …"), so a misread is visible, and the student can correct it.
4. **why-not / what-if play the line** (engine refutation cut by `proofCut`) as a `WalkableLine`; the board walks it and snaps back (existing `walkLine`, lifted to every board surface).
5. `chat` small talk is the ONLY place the model writes words freely, with no toolbelt, no chess vocabulary allowed (the existing strip), and a fixed fallback line.

## 2. One chat surface

- ONE entry `chatTurn(message, ctx)`; `ctx = { surface, fen?, history, seat, register: 'live'|'review', hands }`. Learn, Play chat, the drawer, `/coach/chat` and review all call it. What differs is ONLY `ctx`: the board (or none), the tense, and which hands exist (review has no play/set-position; `/coach/chat` has no board → board questions answer about the last game or offer to open one).
- Learn's ~15 inline pre-routers move behind `chatTurn` (they become fast-path entries), so Learn stops being a second chat.
- One `Record<Kind, Answerer>` and one `Record<Command, …>` — a new kind fails to compile until it is answered on every surface.

## 3. Why this is not the deleted classifier

| deleted `classifyWithLlmFallback` | this |
|---|---|
| ran on EVERY turn | runs only on a fast-path MISS (measured ~40–80% of real turns) |
| guessed a lane LABEL, trusted blindly | fills a closed form that code VALIDATES; illegal SAN / missing piece / no board → rejected |
| a wrong guess answered the wrong question silently | the answer ECHOES the reading; unsure → asks |
| no measurement | ships only after the 554-phrasing matrix + 86 real + 14 tape questions pass (§5) |

## 4. When the model is down (`DEGRADE=llm`)

Stage 2 is skipped; a miss goes straight to 2b: "I didn't catch that — are you asking about: [this move] [their plan] [the best move] [what if…]" as chips, each a pre-built ChatTurn. Never the stock line.

## 5. Proof before it ships (acceptance)

1. Offline: the parser run over 554 matrix phrasings + 86 real + 14 tape → reading accuracy ≥ 95% on the labeled set; every invalid reading caught by validation (0 illegal SANs reach an answerer).
2. The exhaustive routing audit (`audit-coach-all-questions-prod`, muted, real dispatch) green on every surface.
3. The 86 real questions re-asked: ≥ 80% answered what was asked, **0 stock lines, 0 actions not reflected in the words**.
4. `DEGRADE=llm`: 0 stock lines; chips offered.
5. Latency: a miss costs exactly one extra call (flash, no thinking); p90 measured and reported.
6. Emission (the algo-audit rule): one `chat-turn` row per message — fast-path / read / clarified / chat, kind, validated?, echoed — asserted by the routing audit.

## 6. Build order
1. `ChatTurn` schema + validator + `Record<Kind, Answerer>` over the EXISTING assemblers (pure, tested on the question sets offline).
2. The READ stage via `callDeepseekWithTool`; the offline accuracy run (§5.1) — go/no-go.
3. `chatTurn` entry; route the four surfaces through it; delete the banter/legacy free lanes, the `[[ACTION]]` protocol and the prose move net.
4. why-not / what-if line answers + `walkLine` on every board surface.
5. Clarify chips + degraded mode.
6. Prod audit + real-question re-ask; report.

# ✅ FINAL — the design after the skeptic review (supersedes §1–§6 where they differ)

The skeptic checked the draft against the code and confirmed the direction (model fills a closed form → code validates → code acts → words report what was done). Verdict "build with changes". All eight changes are adopted:

**1. Scope: every turn the STUDENT says — typed OR spoken (David 2026-10-04: spoken questions and answers go through the parser too; the earlier "typed only" scope is deleted).** A mic transcript is the same words as a typed question, and a spoken tap-answer ("the knight on c6 and e5") is an `answer` kind. Still NOT touched here, each its own work order: the internal asks the app makes on the student's behalf (hint / phase narration / explore reaction / blunder alert), kid hint and narration text, opening generation, and the position-reading grader (replaced by a deterministic set grader in `2026-10-04-learn-how-to-think.md`). The kid ask box (`GuidedGamePage`) IS in scope, as a declared `kid` surface. Chat gets its own entry whose return type cannot carry free text. Gate: `askSourceFor(...) ∈ {'typed', 'spoken'}`.

**2. A CAPABILITY LEDGER is the gate for every deletion.** Every tool and every free-lane behaviour gets a row: *tool → its new home → test*. No tool is removed until its row is green.
- new COMMANDS (typed, validated, `actuate`d): favorite opening, save to repertoire, clear memory, the 5 settings mutations, review game, continue middlegame, drill / quiz / trap stage, start game {seat, opening?}, start lesson {opening}; set intended opening (deterministic capture added to review, which relies on the model today).
- CODE-SIDE writes, not chat: `record_blunder`, `record_hint_request` move to the blunder / hint paths.
- ANSWERERS: pro player games + player opening moves (the only on-demand path to a pro's games), master games, game export.
- Learn's non-engine step turns become engine-driven BEFORE the prose move-recovery net is deleted (else the board freezes).

**3. Kinds ARE the lanes.** `ChatTurn.question.lane` is the existing lane id, 1-to-1 (`Record<LaneId, Answerer>`), plus slots (move / last-move / piece / seat / game). The 60-lane, 554-phrasing matrix is the labelled set. Learn's move reports ("I played e4") are their own turn type.

**4. Conversation memory, one shape.** A per-surface `ConversationState` rides in `ctx` and comes back with every answer: the pending offer as an executable ChatTurn ("yes" runs it), the last resolved subject + seat ("and for Black?", "the other knight"), the last list ("the second one"), a pending clarification. Chips carry a ChatTurn id, never text to be re-parsed. The parser sees the previous ChatTurn. Replaces the six scattered mechanisms (three module globals, a regex over the model's prose, text chips, the bare-"why?" rewrite).

**5. Parse EVERY student turn (typed or spoken), in parallel; shadow first.** The fast path's WRONG hits are a bigger failure than its misses (the 2026-09-12 greedy-capture bug). The parse runs alongside the fast path (no added latency on a hit); disagreements are logged as a `chat-turn` row. Ship in SHADOW (log only, today's answers served), flip on measured data. Translation is folded into the parse (no serial translate call).

**6. Commands the parser reads never destroy silently.** A parsed (not fast-path) command that would destroy state — reset, set position, take back, navigate away mid-game, start a new game over one in progress — asks for a one-tap confirm. **Starting a game is ALWAYS confirmed and echoed, even when no game is running** (review 2026-09-29: "let's play, I'll be white" → a coach that picked the Caro-Kann is exactly this shape). The parser may NEVER emit a move to play ("what about Nf3?" is always a question). The echo names the resolved referent concretely ("your knight on e5 → Nxe5"), because seat is exactly what a model gets wrong while passing validation.

**7. Extend what exists, don't duplicate.** `dispatchCoachTurn` is already the one entry for Chat, Mic, Masterclass chat, Analyse, Explain-position and GameChatPanel — extend it; only Learn bypasses it. The parser sits AFTER `signalReroute`/`topCandidateLane`. Reuse the existing `[CHOICES:]` / `actionOffer` chip UI. Nine entries, not four.

**8. "One chat" = one CONTRACT, not one module.** Shared: `ChatTurn`, `ConversationState`, the answerers, the commands, the `chat-turn` emission. Per surface: a fast-path registry (Learn registers its walkthrough / stage / trap-menu routers, which read page state and must not be hoisted into a shared module). Each answerer declares what it needs (board / history / nothing); a missing need is a typed offer ("open your last game?"), never a crash or a stock line.

**Degraded (`DEGRADE=llm`):** chips from `topCandidateLane`'s top 3, each a pre-built ChatTurn. **Brief register:** the echo counts inside the 30-word cap.

## FINAL BUILD ORDER — nothing is deleted before step 6
1. `ChatTurn` schema (lane-level) + `ConversationState` + the capability ledger (as a test that lists every tool and its home).
2. Offline eval: the parser (`callDeepseekWithTool`, flash, no thinking) over 554 matrix + 86 real + 14 tape phrasings → reading accuracy per lane; seat accuracy separately. **Go / no-go gate: ≥95% on the 86 real questions + HELD-OUT new phrasings** (review 2026-09-29: the 554 are the regex lanes' own test set, so scoring the parser on them mostly measures agreement with the regex — they are reported separately, never the gate).
3. SHADOW on prod: parse every student turn (typed or spoken) in parallel, log `chat-turn` rows (fast-path lane vs parsed lane, agreed?), serve today's answers. Algo-audit contract rows asserted by the routing audit.
4. Fill the ledger: the new commands and answerers, the conversation state, why-not / what-if as played lines (`WalkableLine` + `walkLine` on every board surface). **`walkLine` draws ONLY through the arrow door** (`arrowDoor.ts`, `lineClaims → admitArrows`; `arrowDoor.gate.test.ts` fails any other arrow constructor).
5. Flip parsed answers on behind a RUNTIME flag (not a build flag — an OTA dispatch ships whatever `main` holds).
6. Delete, student turns only: banter lane, legacy free lane, `[[ACTION]]` protocol, prose move-recovery net — each only when its ledger rows are green.
7. Move Learn's inline routers behind `dispatchCoachTurn` last, one at a time, as its registered fast path.
